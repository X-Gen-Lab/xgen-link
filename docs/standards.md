# 工程约定

本仓采用 X-Gen 工程规范 1.0.0 本地基线。权威正文由 xgen-roadmap 维护，初始已提交来源是 `c018272a1bfa0a0ad0e811ceedcb22862640ed98`。采用范围还含随后形成的 C-020、C-021、DOC-013 空行规则。规范来源与本仓补充执行如下。

## 编码与接口

- 自有生产代码使用 C11，主机 GoogleTest 和 GoogleMock 使用严格 C++17。生产构建默认只编译和安装库。工具、测试与文档按需启用。
- 使用根 `.clang-format`，四空格、同行大括号、指针靠类型和反斜杠 Doxygen。独立定义和声明组之间保留一行；Doxygen 紧邻声明；函数内按责任分段。修改文件遵循已有命名和格式。
- 公共头写清调用上下文、输入和输出单位、所有权、借用截止、失败状态及下一步责任。实现中的注释解释状态转换、顺序、容量和原因，引用公共合同。
- 文档用 UTF-8 和 LF，按读者任务组织。协议定义、公开 API、工具输入、方案与执行证据各有权威源；按[文档维护](zh/development/documentation.md)同步中英页面。
- `tools/quality.json` 固定共享质量源码版本，`tools/quality.py` 是本地和 CI 共用入口。显式准备工具。配置和执行阶段使用当前已准备的来源。

## 设计与评审

| 原则 | 在本仓的约束 |
| --- | --- |
| KISS | 使用显式工作区和固定资源。优先保留单条直接路径及可验证的容量、失败和所有权语义。 |
| YAGNI | 只构建协议实际所需的能力。Boot 通过选择现有档位和资源控制大小。 |
| DRY | 工作区尺寸、报告和初始化共用规划器。CMake 档位派生生成头与安装身份。相同规范由各入口引用。 |
| 单一职责 | Wire 定义编码，parser 组帧，Network 管路由，Transport 管 scope 与可靠状态，workspace 负责资源，产品拥有调度和更新策略。 |
| 开闭原则 | 用现有 profile、配置和窄端口表达装配。新增线上或运行语义同时更新接口、回归和规范。 |
| 替换原则 | 资源提供者满足同一对齐、尺寸和所有权合同。PHY 返回的成功、背压和失败遵守整帧准入。 |
| 接口隔离 | 公开接口暴露协议所需类型与操作。可选能力按受支持的 profile 构建。 |
| 依赖倒置 | 协议使用自有 PHY 与回调合同、显式时间和可选认证 provider。产品或平台适配层连接这些接口。 |

审查 CPU、Flash、RAM、栈及额外间接调用时，用相同工具链、优化、MTU、profile、LTO 和调用路径比较。只有真实目标 ELF 及报告能够建立资源结论。产品另验证板级时延、Flash、DMA、ISR 和完整调用链。

## 验证与证据

新增或修复行为须保留在生产实现上取得的 RED/GREEN。等价搬迁保留既有测试和差分证据。记录 CTest 名称、标签和实际执行结果，性质测试保留可回放种子。将主机、交叉链接、sanitizer、远端 CI、发布和硬件验证分别对应到实际工具、参数和产物。执行入口见[开发工作流](zh/development/workflow.md)和[验证](zh/development/validation.md)。

静态分析读取当前完整的生产编译数据库，覆盖公开头和 `src` 自有实现。所有公开、私有及生成配置头应以 C11 和 C++17 单独首包含。新增局部诊断例外要写明规则、范围、必要性、补偿测试及复核条件。

## 局部诊断说明

| 检查 | 精确范围 | 依据与补偿验证 |
| --- | --- | --- |
| `clang-analyzer-security.insecureAPI.DeprecatedOrUnsafeBufferHandling` | `.clang-tidy` 对可选 Annex K API 检查的排除 | 受支持的 C11 工具链使用通用字节例程；源码检查长度、容量与重叠，其他内存分析和边界测试继续覆盖。 |
| `bugprone-easily-swappable-parameters` | 源码中对应 `NOLINTBEGIN/END` 的单个函数签名 | 相同整数类型具有不同的时间、单位、容量或协议身份。对应调用、向量、会话及边界测试覆盖；参数或调用变化时复核。 |
| `bugprone-casting-through-void` | 已归属协议队列的 `XGL_LIST_ENTRY` 调用行 | 容器宏仅从属于该队列的有效节点恢复拥有对象。回归覆盖移除、重传释放和会话清理。 |
| `clang-analyzer-optin.performance.Padding` | `xgl_transport_peer_state_t` | 主机布局建议不足以决定 MCU 切割。通过实际配置的 workspace 与 ELF 验证，字段排列变化时重测。 |

诊断解释须匹配编译器、ABI 和系统头。缺少正确系统头或编译数据库时修复环境，再运行检查。
