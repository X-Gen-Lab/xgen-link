# 线程安全

一个实例在单一串行上下文中执行。协议不内置锁、线程安全容器变体、全局 mutex 服务或运行时线程安全开关。

## 串行化边界

同一 handle 的全部调用都要串行化，包括发送、step、超时查询、会话变更、stats 和 destroy。优先采用 owner task 或事件循环。多个任务访问同一 handle 时，由应用提供统一锁策略。

不同实例在 workspace 和应用上下文独立时可以独立运行。共享 PHY、分配器或安全 provider 时，仍须由应用同步这些共享对象。

## 回调规则

PHY、接收、认证及错误回调在 API 调用内同步执行，不能重入、重置、关闭或销毁所属实例。应将需要执行的工作入队，等外层调用返回后处理。应用使用递归锁也不能放宽该规则。

接收缓冲仅在回调期间借用，需要长期持有时，须在返回前将接纳的数据复制到应用存储。PHY TX 返回前必须完成帧字节的消费或复制。

## 中断边界

ISR 将字节写入应用存储并通知 owner task，不与任务并发调用 parser、send 或 `xgl_step()`。Ring buffer 的原子性及 ISR/任务可见性由应用保证。

## 停止和销毁

先停止新提交、排除并发 API 调用，并等待当前回调结束，再调用 `xgl_destroy()`。随后才能释放配置、provider/PHY 描述符、上下文和调用者 workspace。
