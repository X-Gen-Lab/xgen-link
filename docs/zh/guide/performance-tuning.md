# 性能调优

调整容量前，先测量所选 profile 和真实驱动。宿主机吞吐及结构体大小不能预测小 MCU 的 Flash、RAM 和最坏延迟。

## 窗口和包容量

较大 peer 窗口可以覆盖 ACK 延迟，但全局 `max_tx_packets` 同时限制总在途量。只有实际流量需要时才一起增加。窗口大于一时还要预留乱序 RX 槽。

可靠消息推进允许用较小包窗口传输较大分片消息，但仍需为每个 peer 保留一个最大消息槽，并显式配置 TX 消息和 RX 重组的字节接纳预算。

## 帧和内存大小

较大帧降低组帧开销，但会增大 parser cache、scratch、可靠 payload 槽及乱序 payload 槽。对每组候选配置调用 `xgl_memory_requirements()`。

池按资源类型分区，并按最大槽尺寸预留。只降低字节接纳预算可能不减少 workspace。应降低 peer 数、包数、帧大小、消息大小或重组槽数，减少对应预留。

Boot 去掉认证、转发、分片、乱序状态及路由索引。使用真实 Cortex-M0 消费者比较 Flash/RAM，不要用静态库文件大小推断最终镜像。

## 调度和复制

根据延迟与唤醒次数调整路由轮询频率。RX 工作按每条链路限定字节预算，回调和 transport 维护仍会增加 step 耗时。

`xgl_send_zerocopy_at()` 只用于支持的单帧非可靠流量。可靠重传和分片消息所有权需要保留副本。同步 PHY 适配层也可能为 DMA 复制到驱动自有缓冲。

## 测量和诊断

记录应用延迟、PHY busy 频率、重传/错误计数和峰值在途量。读取 stats 也须串行化。结合 map、最终 ELF 符号、编译器栈报告和目标栈高水位测量。

单函数 `.su` 最大值不能代表调用链或中断栈上限。Boot 测量包含消费者和通用启动代码，不含你的 BSP 和应用缓冲。更小的 Boot 设计目标，在测得满足前仍只是优化目标。
