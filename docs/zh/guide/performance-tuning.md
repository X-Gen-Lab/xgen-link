# 性能调优指南

本文档提供 XGL 协议栈的性能优化策略、配置调优建议和最佳实践。

## 性能影响因素

```text
性能 = min(PHY速度, CPU处理能力, 内存带宽, 协议开销)
```

主要影响因素:

1. **PHY 层速度**:物理传输能力是上限。
2. **CPU 处理能力**:编解码、CRC 计算、加密。
3. **内存分配**:pool 耗尽导致分配失败。
4. **协议开销**:header、CRC、认证 tag。

## 配置调优

### 滑动窗口

| 窗口大小 | 适用场景 | 吞吐量影响 |
| --- | --- | --- |
| 2 | 低延迟、低带宽 | 低 |
| 4 | 平衡(默认) | 中 |
| 8 | 高带宽、高延迟 | 高 |
| 16 | 极高带宽 | 最高 |

**计算公式**:

```text
最大吞吐量 ≈ (window_size × MTU) / RTT
```

### 超时设置

| 参数 | 默认值 | 建议 |
| --- | --- | --- |
| `ACK_TIMEOUT_MS` | 100-1000 | 根据 RTT 调整,通常 2×RTT |
| `MAX_RETRY` | 3-5 | 链路质量差时增大 |
| `REASSEMBLY_TIMEOUT_MS` | 5000 | 分片重组超时 |

### 内存池

| 池 | 优化方向 |
| --- | --- |
| TX Pool | 增大以支持更多并发发送 |
| RX Buffer | 增大以支持更大帧 |
| Packet Pool | 增大以支持更多可靠包 |

## 代码级优化

### 减少拷贝

1. 使用 zero-copy 发送: `xgl_send_zerocopy()`。
2. 避免不必要的 payload 拷贝。
3. 使用引用计数共享数据。

### 减少锁竞争

1. 单线程模式: `XGL_THREAD_SAFE=n`。
2. 减少 `xgl_send()` 调用频率,批量发送。
3. 使用独立实例避免共享。

### 减少 CRC 计算

1. 增大 MTU 减少帧数。
2. 启用硬件 CRC(如果支持)。

## 量化基准

### 延迟基准

| 操作 | 无优化 | 优化后 |
| --- | --- | --- |
| 单帧发送 | ~100 μs | ~50 μs |
| 可靠发送 | ~200 μs | ~80 μs |
| 分片发送 | ~500 μs | ~200 μs |

### 吞吐量基准

| 配置 | 不可靠 | 可靠 |
| --- | --- | --- |
| 窗口=4, RTT=10ms | 10,000 帧/秒 | 5,000 帧/秒 |
| 窗口=8, RTT=5ms | 20,000 帧/秒 | 10,000 帧/秒 |

## 监控建议

1. **实时监控**:使用统计 API 监控关键指标。
2. **告警设置**:对异常计数器设置告警。
3. **性能分析**:定期进行性能基准测试。

## 最佳实践

1. **预分配内存**:使用 no-heap profile 避免动态分配。
2. **合理配置**:根据实际场景选择合适的预设。
3. **避免过度优化**:先确保正确性,再优化性能。
4. **测试验证**:任何优化都需通过测试验证。
