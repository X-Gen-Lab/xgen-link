# 分片

Embedded 与 Full 可以启用有界协议分片。Boot 不包含此功能；固件传输块由 Boot 应用协议管理。各 profile 保持相同 wire 编码，但不支持分片的接收方不能接纳分片消息。

## 分片身份与边界

FRAGMENT_EXT 使用三个 32 位值携带 `message_id`、`offset` 和 `total_len`。重组键由精确 peer scope 与消息 ID 组成。总长度必须非零、不超过显式 `max_message_size` 和字节预算，并在各片之间保持一致。偏移与长度在加法或复制前校验。每个未完成消息最多保存 16 个接收区间。

完全覆盖的重复区间必须具有相同字节。部分重叠区间会被拒绝：没有保留的新字节不能被确认。仅当覆盖范围达到声明的完整长度时，消息才算完成。

## 可靠消息推进

需要分片的可靠提交为每个 peer 持有一份有界的完整应用消息副本。仅当该 peer 的窗口和全局 TX 记录预算允许时，分片才进入可靠队列。ACK 处理与后续 step 会继续推进未发送尾部，窗口为一时也能完成。每片有自己的可靠 DATA 编号；重传保留编号与分片元数据。

全部分片进入自有可靠记录后释放完整消息副本。本地 BUSY 或临时内存压力会保留已接纳消息并安排有界延迟重试。硬错误或重试耗尽会终止 scope，释放其持有数据并报告失败。提交成功表示接纳，不表示远端应用处理完成。

## 接收所有权与失败

未完成重组槽、全部保留的重组字节与待投递完整消息都受显式容量限制。最后一片完成后，应用返回 BUSY 时完整消息继续由 peer 持有，后续 `xgl_step` 重试投递。应用恢复容量后必须再次驱动 step。已 ACK 的可靠未完成消息不能静默过期：过期时先使 scope 失败，再释放存储。

非可靠分片同步逐片提交，不具备可靠消息的完整副本重试契约。后续提交发生错误时，前面的片可能已经发出。需要恢复能力的应用应使用可靠消息或应用层块协议。

验证依据：`test/unit/transport/test_fragment.cpp` 与 `test/unit/transport/test_transport.cpp`。
