# 压缩与加密

当前实现不支持压缩或载荷加密。认证是独立能力，参见[安全](security.md)；认证标签不会隐藏载荷字节。

## 拒绝的配置

公开功能配置启用压缩或加密时返回 `XGL_ERR_UNSUPPORTED`。发送时选择非零压缩标识会明确拒绝，不会静默忽略。协议库中没有 codec 注册器。

## Wire 兼容

不能把本地数据变换当成可互操作的 wire 能力。未来引入 codec 前，必须定义算法标识、膨胀上限、认证元数据、接收接纳规则，并通过双向互操作测试。仅有保留的 wire 标志或扩展类型不能提供这些契约。

## 应用数据变换

双方约定应用格式后，应用可以先编码消息体再提交。编码后最大长度必须满足配置的载荷或消息上限，解码长度上限由应用负责。这不等于启用了协议的压缩或加密配置。
