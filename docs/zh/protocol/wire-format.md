# 线格式

wire version 为 `3`。除特别说明外，整数字段使用小端序。帧布局为 `基本帧头 | TLV | 载荷 | 可选认证标签 | 整帧 CRC16`。基本帧头为 24 字节；`header_len` 包含所有 TLV，最大为 255。

## 基本帧头

| 偏移 | 字节数 | 字段 |
| --- | --- | --- |
| 0 | 2 | 魔数 `A5 5A` |
| 2 | 1 | 版本 `03` |
| 3 | 1 | 总帧头长度 |
| 4 | 1 | 报文类型 |
| 5 | 1 | 标志 |
| 6 | 1 | TTL |
| 7 | 1 | 流量类别 |
| 8 | 2 | 源节点 ID |
| 10 | 2 | 目标节点 ID |
| 12 | 4 | Connection ID |
| 16 | 4 | 可靠 DATA 包号 |
| 20 | 2 | 载荷长度，不含标签和 CRC |
| 22 | 2 | 帧头 CRC16 |

节点零无效；`0xFFFF` 表示广播。DATA、ACK、CONTROL 的类型分别为 1、2、3。其他已声明报文类型只保留编码值，不代表另有已实现的应用服务。DATA_TYPE 使用独立扩展，因此应用类型不会被误当作控制报文。

## 校验与编号

两种 CRC 均为 CRC-16/MODBUS，结果按小端编码。帧头 CRC 覆盖 24 字节基本帧头，计算时将第 22、23 字节置零。整帧 CRC 覆盖其前的所有字节，包括 TLV 和认证标签。解码器校验完整边界、精确的载荷及标签长度、单例 TLV，然后才返回借用视图。认证标志只表明携带标签，认证是否有效由安全模块判定。

每个 peer scope 的可靠 DATA 从零开始，仅在首次发送被接纳后递增；重传保持包号。ACK、CONTROL、非可靠 DATA 的帧头包号为零，被确认的包号只出现在 ACK_RANGE 或 SACK 中。可靠序号耗尽前必须切换到新 epoch。

## 大小预算

载荷预算为 `MTU - 24 - TLV 字节数 - 标签字节数 - 2`。携带单区间 ACK、SESSION、SECURITY 和 16 字节标签的 ACK 长度为 `24 + 15 + 14 + 15 + 16 + 2 = 86` 字节。128 字节控制预留可容纳该示例。当前 Boot 构建不包含认证；此处是线格式预算，不表示认证 Boot 也能放进相同 RAM 配置。

验证依据：`test/test_wire.cpp`。
