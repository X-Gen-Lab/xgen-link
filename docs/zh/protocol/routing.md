# 路由

一条路由把目标节点映射到 PHY 及其完整帧 MTU。路由属于协议配置，通用哈希/链表存储属于 xgen-containers。声明的路由容量固定，耗尽时返回错误，不静默扩容。

## 查找与容量

已有路由可以更新，删除后的槽可以复用。未知目标返回路由不存在。Boot 使用有界线性查找；Embedded 与 Full 可使用编译后的路由索引。发送规划考虑链路 MTU，以及 SESSION、FRAGMENT、SECURITY、标签和 CRC 的开销。

包身份与选择的路由无关。更换 PHY 或 MTU 不会重置精确 transport scope、DATA 编号或安全关联。应用应避免把路径改成无法承载已接纳包的 MTU。

## 转发

Boot 编译时裁剪转发。启用的转发节点验证完整帧，要求目标路由，检查出口完整帧 MTU，并拒绝不足以再经过一跳的 TTL。然后取得有界 scratch，递减 TTL，重写帧头 CRC 与最终 CRC，再同步发送。

端到端认证标签与被认证载荷保持不变。AAD 规范化排除了 TTL 和帧头 CRC；转发不会安装本地信任，也不声称已验证目标标签。目标为本机的认证帧在 transport 投递前完成验签。

## 广播与可靠性

广播使用节点 `0xFFFF`。认证策略允许时支持明文广播。认证实现只支持单播关联。不能把广播当成组可靠投递或组认证协议。双方容量与功能兼容性由应用配置，路由发现不会协商 transport 窗口或可信 epoch。

验证依据：`test/unit/network/test_network.cpp`。
