# 平台与 Profile

可移植协议核心需要 C 工具链及五个独立基础包，具体版本和入口见[模块化迁移](../guide/modular-migration.md)。应用提供显式时间、PHY 回调、存储与串行访问。库不包含全局时间提供器、OS 互斥子系统或自动堆回退。

## 执行契约

使用 `xgl_send_at(handle, data, now_ms)`、`xgl_step(handle, now_ms, budget)` 和 `xgl_next_timeout(handle, now_ms, &delay)`。全部调用采用同一个按 2^32 回绕的单调毫秒时域；相关间隔与经过时间比较必须小于半范围。超时查询显式返回是否存在期限，因此零是合法的立即到期延迟。

工作预算约束每条链路的接收字节并提供接收超时。协议工作还受配置的 peer、包与消息数量限制。新 RX 数据到达和应用恢复接收容量都应触发下一次 step。本地 TX BUSY 重试有正数有界定时。调用方串行操作同一实例；回调不得重入或销毁实例。多个实例可以独立调度。

## 编译 Profile

| 能力 | Boot | Embedded | Full |
| --- | --- | --- | --- |
| Wire 版本 | 3 | 3 | 3 |
| 认证 | 裁剪 | 包含 | 包含 |
| 安全会话槽，包含已关闭标记 | 0 | 4 | 16 |
| 分片与乱序存储 | 裁剪 | 包含 | 包含 |
| 转发与路由索引 | 裁剪 | 包含 | 包含 |
| 可靠索引桶数 | 1 | 32 | 32 |
| 构建配置 ID | 301 | 302 | 303 |

编译包含的功能仍需要有效运行时配置与显式容量。全部 profile 拒绝尚不支持的压缩/加密。构建专属公开头文件必须与编译库匹配，ABI/profile 检查会拒绝不匹配组合。

## 小型 Boot 部署

小型 Boot 配置使用静态工作区、一条链路、一条路由、一个 peer、一条可靠 TX 记录和窗口一。128 字节 MTU 可作为基线。Full 节点与其通信时必须使用 wire v3、兼容的认证策略、不使用通用分片，并限制发送窗口为一。协议不会自动协商这些容量。

固件传输使用有界应用块。Transport ACK 只确认接纳；Boot 应用在 Flash 写入/校验完成后另行发出持久提交响应。应用定义镜像身份、偏移、恢复状态、重试策略与最终校验。64 KB Flash / 8 KB RAM 目标必须结合实际目标 link map、静态工作区需求与最坏栈占用验收，宿主机尺寸不能证明该预算。
