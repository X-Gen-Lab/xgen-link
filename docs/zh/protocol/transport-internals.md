# Transport 内部结构

Transport 唯一负责可靠状态转换。辅助模块按状态所有者及借用/自有数据契约划分，而不按可替换的通用算法划分。

## Peer 状态与辅助模块

`xgl_transport_peer.c` 完成精确查找、有界创建、终态失败与显式 close。每个 peer 包含 TX 窗口、等待 ACK 队列、RTT 估计器、下一 RX 编号与可选的保留接收/消息状态。上下文保存配置容量、显式当前时间、资源服务与 peer 列表。不存在第二个全局窗口或短会话身份。

队列、索引和窗口辅助模块操作已选 peer 的对象，不选择回退 peer、不重置 scope，也不提交原始 PHY 字节。`xgl_transport_ack.c` 在改变记录、窗口或 RTT 前验证全部声明。大于等于下一未分配 TX 编号的包不能成为有效 ACK 目标。

## 跨调用所有权

当前 17 个实现文件按生命周期划分：入口负责初始化和销毁；`peer` 负责身份、回收和发送资格；`tx` 负责完整请求预检、接纳与提交，`tx_message` 推进跨窗口消息；`rx` 判定接收顺序，`rx_buffer` 保存乱序包，`rx_delivery` 统一应用交付；`ack` 解释反馈，`ack_send` 组织 ACK/SACK；`runtime` 处理重试、超时和 deadline；`control` 处理控制帧。`reliable`、`window`、`rtt` 与三个 `fragment` 文件保留独立算法边界。

发送预检在创建 peer 或发送 HELLO 前完成。可靠接纳直接返回拥有的记录，不再二次查找。ACK 扩展只扫描一次 TLV；通过全量校验后先应用全部确认，再执行快重传，因此 PHY BUSY 不会阻断同一反馈中的后续有效确认。

| 输入或保留状态 | 契约 |
| --- | --- |
| 发送请求 | 调用期间借用；已接纳可靠字节被复制 |
| 接收包/帧 | 借用至同步回调返回 |
| 可靠记录 | 持有载荷和分片元数据，直到完成或终止 |
| 乱序包 | 可以被 SACK 前已持有载荷与 TLV |
| 完整 RX 消息 | 应用返回 BUSY 时由 peer 保留 |
| 待发送 TX 消息 | 跨窗口等待和本地容量停顿保留未发送尾部 |

每次分配通过同一资源服务释放。清理 peer 数据不重置其身份、已消耗 DATA 编号或终态失败标志。安全重放与认证计数器不属于此清理过程。

## 调度与可观察结果

`xgl_transport_run` 接收公开 step 操作传来的显式时间。超时汇总器组合等待 ACK 的期限、正数本地重试延迟、可回收未使用 peer 的空闲期限以及分片过期时间。不存在可能随 peer 队列变化而失效的全局最早期限缓存。

超时重试和 SACK 触发重试经过相同逻辑包路径。临时 BUSY 或内存压力保留已接纳存储并安排再次尝试。硬失败、重试耗尽、已确认重组过期与 RESET 都会可观察地终止 scope。错误回调同步执行，不得重入实例。应用恢复容量后，应再次 step 以投递因 BUSY 保留的接收数据。
