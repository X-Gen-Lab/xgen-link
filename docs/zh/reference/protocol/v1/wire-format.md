# 线格式

Wire 版本为 `1`。除特别说明外，整数字段使用小端序。帧布局为 `基本帧头 | TLV | 载荷 | 可选认证标签 | 整帧 CRC16`。基本帧头为 24 字节；`header_len` 包含所有 TLV，最大为 255。

## 基本帧头

| 偏移 | 字节数 | 字段 |
| --- | --- | --- |
| 0 | 2 | 魔数 `A5 5A` |
| 2 | 1 | 版本 `01` |
| 3 | 1 | 总帧头长度 |
| 4 | 1 | 报文类型 |
| 5 | 1 | 标志 |
| 6 | 1 | TTL |
| 7 | 1 | 流量类别 |
| 8 | 2 | 源节点 ID |
| 10 | 2 | 目标节点 ID |
| 12 | 4 | Connection ID |
| 16 | 4 | 可靠 DATA 包号 |
| 20 | 2 | 载荷长度，不含标签和 CRC |
| 22 | 2 | 帧头 CRC16 |

节点零无效；`0xFFFF` 表示广播。DATA、ACK、CONTROL 的类型分别为 `1`、`2`、`3`。Wire 拒绝其他报文类型。DATA_TYPE 使用独立扩展，因此应用类型不会被误当作控制报文。端点准入拒绝可靠广播，非可靠广播仍受路由及认证策略约束。

## 标志与流量类别

标志位 `0x01` 表示请求确认，`0x02` 表示含扩展，`0x04` 表示含认证标签，`0x08` 标记控制帧。未分配的标志位必须为零。

流量类别低三位表示优先级，第 6–7 位表示可靠性。取值 `0x00` 表示不请求确认，`0x40` 表示请求确认，`0x80` 表示纯 ACK。第 3–5 位未分配，必须为零。

扩展标志仅在 `header_len > 24` 时置位。报文类型决定合法的可靠性取值、标志和帧头字段。

| 类型 | 可靠性 | 请求确认 | 控制标志 | 包号和载荷 |
| --- | --- | --- | --- | --- |
| DATA（非可靠） | `0x00` | 清零 | 清零 | 包号为零 |
| DATA（可靠） | `0x40` | 置位 | 清零 | 帧头包号标识可靠 DATA |
| ACK | `0x80` | 清零 | 清零 | 包号和载荷长度均为零 |
| CONTROL | `0x00` | 清零 | 置位 | 包号和载荷长度均为零 |

## 校验与编号

两种 CRC 均为 CRC-16/MODBUS，结果按小端编码。帧头 CRC 覆盖 24 字节基本帧头，计算时将第 22、23 字节置零。整帧 CRC 覆盖其前的所有字节，包括 TLV 和认证标签。解码器校验完整边界、精确的载荷及标签长度，以及 DATA_TYPE、SESSION、SECURITY 的单例约束，然后才返回借用视图。完整帧解码与逐步流解析共用 Wire 的字段、长度与 CRC 校验。版本字段必须为 1。结构合法的未知非关键 TLV 可被跳过。认证标志只表明携带标签，认证是否有效由安全模块判定。

每个 peer scope 的可靠 DATA 从零开始，仅在首次发送被接纳后递增；重传保持包号。可用 DATA 编号止于 `UINT32_MAX - 1`；发送和接收均拒绝可靠 DATA 使用 `UINT32_MAX`，接收历史不会回绕到零。ACK、CONTROL、非可靠 DATA 的帧头包号为零，被确认的包号只出现在 ACK_RANGE 或 SACK 中。可靠序号耗尽前必须切换到新 epoch。

## 大小预算

载荷预算为 `MTU - 24 - TLV 字节数 - 标签字节数 - 2`。携带单区间 ACK、SESSION、SECURITY 和 16 字节标签的 ACK 长度为 `24 + 15 + 14 + 15 + 16 + 2 = 86` 字节。128 字节控制预留可容纳该示例。当前 Boot 构建不包含认证；此处是线格式预算，不表示认证 Boot 也能放进相同 RAM 配置。

验证依据：`test/unit/wire/test_wire.cpp` 与 `test/unit/transport/test_transport_rx_contracts.cpp`。
