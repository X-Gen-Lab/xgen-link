# 路由

一条路由把目标节点映射到 PHY 及其完整帧 MTU。路由属于协议配置，Network 层持有固定路由表与可选的私有索引。容量耗尽时返回错误。

## 查找与容量

实例初始化拒绝目标为零、本机 ID 或重复目标的静态配置。广播目标允许显式配置。整表加载在替换前检查无效目标、空 PHY 和重复目标；拒绝的配置不会清除已有路由。未知目标返回路由不存在。Boot 使用有界线性查找，其他当前 profile 使用固定 16 桶索引。发送规划考虑完整帧 MTU，以及 SESSION、FRAGMENT、SECURITY、标签和 CRC 的开销。

`metric` 是保留的兼容字段，不参与出口选择，也不提供多路径择优。私有路由表仍支持更新已有目的和复用删除后的槽；查询返回的借用指针可能在删除、加载或清空后失效。

## 链路装配与生命周期

实例借用的配置必须保持有效且不可变，直到销毁。工作区规划与链路初始化共用 PHY 首次出现的判定，每个唯一 PHY 只建立一个 parser 和接收缓存。多个目的可以共用 PHY；其 `read_freq_hz` 初始化提示合并为最短轮询周期，与配置顺序无关。毫秒调度下非零频率的最短周期为 1 ms。

路由表只负责目的出口，链路对象负责轮询和接收存储。兼容配置仍使用同一个公开结构，未增加第二份配置副本。私有路由增删不注册新 PHY、不重建接收缓存，也不改变已确定的轮询周期；公开 API 不承诺运行时链路热更新。当前仍需通过路由配置注册 PHY，没有独立的仅接收链路配置入口。

包身份与出口选择分开。更换私有路由不会重置 transport scope、DATA 编号或安全关联；但这不代表可以把已接纳包迁移到更小的 MTU。需要动态链路管理的产品应先定义容量、停用、在途包和回滚契约。

## 转发

Embedded 和 Full 支持转发。转发节点验证完整帧，要求目标路由，检查出口完整帧 MTU，并拒绝不足以再经过一跳的 TTL。然后取得有界 scratch，递减 TTL，重写帧头 CRC 与最终 CRC，再同步发送。

端到端认证标签与被认证载荷保持不变。AAD 规范化排除了 TTL 和帧头 CRC；转发不会安装本地信任，也不声称已验证目标标签。目标为本机的认证帧在 transport 投递前完成验签。

正常 datalink → network 端点必须携带已验证的借用 view，不再接受 raw 回退。独立的私有 raw 接收函数保留完整解码和实例帧长检查。转发从 view 取得唯一的帧地址和长度，不修改 parser 缓存；同步 serialized 提交复用同一份 scratch，不再申请第二份整帧。

下层提交失败保留原始错误，例如 `XGL_ERR_BUSY`，并释放 scratch。没有中继排队或自动重试承诺；可靠性由端点 transport 负责。返回值是本次操作的权威结果，错误回调仅报告指定事件，并不覆盖所有错误返回。

中继不重新分片、不协商路径 MTU。源端应按路径瓶颈配置发送上限。可靠 A → B → C 通信还需要 C 的“目的 A、出口经 B”路由供 ACK 返回；只有到邻居 B 的路由不够。RX view 不携带入口 PHY，目的路由查找不等于来源授权。

本地可靠 DATA 在交付或保留前检查反向出口及反馈帧预算。缺路由时返回 `XGL_ERR_ROUTE_NOT_FOUND`，出口容量不足时返回 `XGL_ERR_BUFFER_TOO_SMALL`。要求认证的反馈还会检查反向会话是否有可用安全序号，耗尽时返回 `XGL_ERR_SEQUENCE_ERROR`。预检不消耗序号。预算计入非零 epoch 和出站认证标签。例如单区间 ACK、非零 epoch 和 16 字节标签共需 86 字节。应用接纳后遇到 PHY 背压时保留接收历史，以便重传触发再次反馈。产品分别验证正向 DATA 和反向反馈的每一跳。

## 广播与可靠性

广播使用节点 `0xFFFF`。认证策略允许时支持明文非可靠广播。可靠广播提交在创建 transport 所有权前返回 `XGL_ERR_INVALID_PARAM`；接收到请求确认的广播时，在改变 peer 历史或发送反馈前返回 `XGL_ERR_INVALID_FRAME`，不能消耗同一来源的单播 DATA 编号。认证实现只支持单播关联，不提供组可靠投递或组认证协议。双方容量与功能兼容性由应用配置，路由发现不会协商 transport 窗口或可信 epoch。

收到广播只执行本地交付，不跨 PHY 泛洪；发送广播需要显式广播出口。TTL 只限制继续转发：0/1 不可转发，本地目的帧仍可交付。查出口先于 TTL 检查，因此同时无路由且 TTL 过期时返回 `XGL_ERR_ROUTE_NOT_FOUND`。
