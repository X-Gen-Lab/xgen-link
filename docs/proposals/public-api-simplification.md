# XGen Link 对外 C 接口评审与精简方案

本方案评审 SDK 0.0.1 当前工作树，基线提交为 `cf21e83`，包含其后尚未提交的运行时预设、配置 ABI 编号及构建编号清理。下文的“当前”指这份源码，“建议”指待实施的改动。产品继续自行初始化 `xgl_config_t`。现行合同见[公开 API](../zh/reference/api.md)，评审依据见[工程约定](../standards.md)。

## 1. 对应用来说，问题有多大

仅包含 `<xgl/xgl.h>`，C11 编译器就能看到 **28 个可调用函数名和 35 个具名类型**。但一个使用静态工作区的收发端，只需掌握以下五个函数。

| 应用要做的事 | 推荐入口 | 应用承担的责任 |
| --- | --- | --- |
| 计算工作区 | `xgl_memory_requirements` | 填好地址、容量、超时、路由和 PHY。检查错误、字节数和对齐 |
| 启动实例 | `xgl_init_static` | 提供对齐、足量、地址稳定的空间。成功返回的实例已初始化 |
| 发送一个 DATA 帧 | `xgl_send_at` | 提供单调毫秒时钟，按返回值处理本机准入。业务交付确认由应用定义 |
| 轮询链路、推进协议 | `xgl_step` | 由同一执行者调度，指定每条链路的 RX 字节预算和半帧超时。接收通过同步回调交付 |
| 结束实例 | `xgl_destroy` | 先让所有调用和回调退出。销毁完成后才能复用静态工作区和借出的对象 |

这条路径已经在 echo、文件分块传输和多节点转发示例中使用。测量工作区会经过配置校验，应用需要单独诊断配置时再调用 `xgl_config_validate`。需要低功耗调度时再引入截止时间查询。首读教程应先完成一次收发，再链接这些分支。[示例的工作区和调度代码](../../examples/common/sim_link.h) · [工作区规划实现](../../src/api/xgl_workspace.c)

### 实际安装和调用结果

从工作树分别构建、安装 Boot 和 Full 的 Release 静态库，高级运行时使用默认关闭值。用 Clang 14 对只包含公共总头的 C11 翻译单元取 AST，按 `xgl_` 名称去重。函数指针 typedef 计入类型，结构体内的回调成员和宏另计。用 GNU `nm -g --defined-only` 统计归档中类型为 `T` 的不同 `xgl_*` 符号。

| 观测值 | Boot | Full | 用途 |
| --- | ---: | ---: | --- |
| 安装的头文件 | 5 | 5 | 4 个源码头和 1 个生成的构建配置头 |
| 应用可见函数名 | 28 | 28 | 主头声明 27 个，错误头另有 `xgl_error_string` |
| 其中 `static inline` / 其余外部函数 | 0 / 28 | 0 / 28 | 所有公开函数均可按声明的同名符号链接 |
| 可见的命名 typedef | 35 | 35 | 包括句柄、参数、返回结构、回调和错误类型 |
| 归档 `xgl_*` 全局代码符号 | 156 | 176 | 其中 128 / 148 个没有公共函数声明，主要供库内跨文件调用 |

切换档位会改变库内实现和能力。两档安装头提供相同的函数名，关闭能力的入口有各自的错误合同。主头直接声明创建、测量和静态初始化函数，应用调用时只传入该操作所需的参数。将归档符号总数用作 SDK 精简指标，会把生产模块之间的正常调用也当作产品接口。[安装清单](../../cmake/XglInstall.cmake) · [API 参考入口](../zh/reference/c-api.md) · [统计能力关闭时的行为](../../src/api/xgl_stats.c)

用宿主 C11 编译器仅添加安装前缀的 `include`，链接该前缀的 `libxgl.a`，实际结果如下。公开函数使用数包含示例共享头中的调用，排除注释和应用自己的辅助函数。

| 消费者 | 观测 |
| --- | --- |
| `echo_server`、`file_transfer` | 两档都编译、链接并运行成功。每个示例各用上述 5 个公开函数 |
| `multi_node` | 在支持转发的 Full 档编译、链接并运行成功，也只用上述 5 个函数 |

## 2. 逐项处置全部 28 个函数

表中函数名均省略共同的 `xgl_` 前缀。分组互斥，覆盖安装头中的全部名称。

| 职责 | 数量 | 当前函数 | 建议与理由 |
| --- | ---: | --- | --- |
| 配置、存储与生命周期 | 8 | `config_validate`、`memory_requirements`、`memory_report`、`init_static`、`create`、`create_with_error`、`init`、`destroy` | 静态路径为首选。动态路径推荐 `create_with_error` → `init`，将只返回指针的 `create` 列为退役候选。保留单独校验、轻量测量和按类报告，它们回答不同问题 |
| 显式高级策略 | 3 | `memory_report_with_options`、`create_with_options`、`init_static_with_options` | 集中在高级运行时一页。只有产品使用限时发送、作用域回调等策略时才引入描述符。普通 Boot 收发无需填写空 options |
| 发送 | 4 | `send_at`、`send_zerocopy_at`、`send_zerocopy_layout`、`send_zerocopy_scoped_at` | 普通提交为主路径。原地发送保留“查询布局＋按作用域提交”。旧的零作用域提交可由同一作用域请求表示，列为退役候选 |
| 运行与低功耗 | 4 | `step`、`step_bounded`、`next_timeout`、`next_timeout_for_work` | 主循环首选 `step`。需要限制单次解析候选和 TX 尝试时用有界入口。两种超时查询依赖不同的预算和历史状态，应分别说明 |
| 可信会话与 peer | 3 | `install_security_session`、`close_security_session`、`close_peer` | 显式安装可信参数。两个关闭动作分别拥有认证状态和传输状态，保留独立入口及操作顺序 |
| 观测 | 3 | `stats_get`、`stats_reset`、`resources_get` | 前两项读取和复位统计，后一项查询当前占有的资源。按“统计”“当前占用”组织查询说明，注明各自能力开关 |
| 版本与错误解释 | 3 | `version_string`、`version_int`、`error_string` | 留在诊断参考。库版本用于识别实际链接的实现，编译期宏来自使用者的头。弱化版错误文字也须保留实际错误码供应用决策 |

据此，**第一轮把普通收发路径收敛到 5 个推荐函数**。若未来另行决定退役指针式创建和旧零作用域发送，且不增加其他函数，对外名称将由 28 个降至 26 个。移动头文件或文档分组单独记为可发现性改进，不能计作已删除函数。归档字节、固件 Flash 和工作区大小用各自的目标产物测量。

## 3. 哪些可以合并，哪些行为需要单独表达

评审按仓库规范取舍。**KISS 和接口隔离**要求普通静态端点能独立完成收发，高级预算、认证和诊断按需发现。**DRY 和单一职责**要求尺寸测量共用规划器，同时让每个公开操作交代由谁持有或释放资源。**YAGNI**优先清理已经有等价替代的入口和不能启用的选项。**依赖倒置与替换原则**落实在 PHY、allocator 和认证 provider 的窄端口上。更换实现后，PHY 仍须在返回前消费整帧，allocator 仍须满足对齐和释放合同，provider 仍须遵守同步借用约定。**开闭原则**通过既有能力开关引入可选行为，基本调用者无需填写无关参数。[设计与评审规则](../standards.md)

### 创建与错误交付

`xgl_create` 调用 `xgl_create_with_error` 后只返回句柄，丢弃具体错误。两者都只预留实例。动态分配失败和参数无效对产品有不同的恢复处理，推荐带错误码的入口。创建成功后若 `xgl_init` 失败，调用者仍负责销毁已预留句柄，释放动态工作区。静态入口内部完成初始化，失败时清空输出句柄，空间仍归调用者。[预留与静态初始化](../../src/api/xgl_workspace.c) · [初始化和销毁](../../src/api/xgl_instance.c)

旧指针式调用迁移时，错误处理可以直接写在应用已有的启动函数里。下例中的 `config` 已由应用构造并保持有效，成功后由调用者管理 `handle`。

```c
xgl_handle_t handle = NULL;
xgl_error_t error = xgl_create_with_error(&config, &handle);
if (error != XGL_OK) {
    return error;
}
error = xgl_init(handle);
if (error != XGL_OK) {
    xgl_destroy(handle);
    return error;
}
```

`memory_requirements` 和 `memory_report` 已复用工作区规划器。前者只交付尺寸、对齐等启动数据，后者还统计分类字节。DRY 应落实到共享计算，Boot 调用者仍可使用较小的输出对象。普通创建、测量和静态初始化函数直接从静态库链接。应用使用同一份 SDK 的头和库；CMake 消费可检查资源标识及导出目标冲突，直接链接归档时由产品保证配套。[公开声明](../../include/xgl/xgl.h) · [工作区规划实现](../../src/api/xgl_workspace.c)

### 常规发送、原地发送和接收背压

- 普通发送在调用内借用输入，可靠发送需要在协议自有的有界存储中保留数据以重传。原地发送使用应用可写帧缓冲，当前只支持非可靠发送，PHY 返回前必须消费或复制所有字节。把二者合为同一个带模式开关的请求，会引入无效的缓冲区、可靠性和生命周期组合。
- 旧 `send_zerocopy_at` 固定 connection ID 和 epoch 为零。常规成功路径可将旧描述符赋给 `xgl_tx_zerocopy_request_t.data`，两个 scope 字段置零，再用 `send_zerocopy_scoped_at`。先用 `send_zerocopy_layout` 求出载荷偏移和总容量，实际发送再次验证当前状态。布局查询既不送帧也不消耗安全序号。
- 兼容阶段须保留旧调用的失败顺序。例如未初始化句柄同时搭配空请求时，旧入口先检查实例状态，scoped 入口先检查请求指针。应保留原包装的检查顺序并做差分验证。应用迁移失败路径时按新入口的合同处理。
- 接收回调目前有三种。普通 `rx_callback` 无返回值，有背压的应用使用 `rx_accept_callback`，高级 `rx_scoped_callback` 还提供连接、epoch 和可靠性。实际优先级为 scoped → accept → 普通。scoped 使用 options 的回调上下文，另两种使用配置的回调上下文。建议普通产品优先接入 accept，新文档同时标出 `BUSY`、`NO_MEMORY`、重试和已缓存乱序包的责任。保留只发送端不安装接收回调的用法。

### 调度、会话与观测

| 看起来相近的操作 | 产品能观察到的区别 | 评审结论 |
| --- | --- | --- |
| `next_timeout` / `next_timeout_for_work` | 前者纳入所有 PHY 轮询并使用最近 step 的半帧策略。后者按拟用预算计算，RX 预算为零时排除轮询，仍计入适用的 transport 和半帧截止时间。返回 false 时不改写输出 | 保留两个合同。低功耗示例使查询预算与下一次 step 一致，覆盖零 RX、时钟回绕、无截止事件和外部唤醒 |
| `step` / `step_bounded` | 后者另有限额和 pending 输出，要求高级运行能力。零限额仍需处理相应定时事务，应用 BUSY 后可能需要外部唤醒 | 把限额和续调示例放到高级页。基本函数保持显式时间、单一执行者和每链路 RX 预算 |
| `close_peer` / `close_security_session` | 存活的认证会话拒绝普通 peer 关闭。关闭认证会话要先关闭安全关联、保留已用 nonce 域记录，再清理匹配的 transport scope | 保留两种关闭操作。测试核对取消通知、已安装会话、仅存安全状态时的结果，以及关闭后对旧流量的处理 |
| `memory_report` / `stats_get` / `resources_get` | 分别回答规划预留多少字节、运行累计发生了什么、当前还持有多少 peer 和包。复位统计会保留工作区的预留计数 | 保留各自的读写成本、时间点和能力要求。基本工作区测量不依赖统计或高级运行时 |
