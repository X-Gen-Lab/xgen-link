# ADR 0002：资源所有权和执行上下文

状态：已采用。

## 执行模型

协议实例由调用者串行执行。公开发送使用 `xgl_send_at()` 或 `xgl_send_zerocopy_at()`，维护使用 `xgl_step()`，调度使用 `xgl_next_timeout()`。时间由同一单调 32 位毫秒源显式传入，不安装全局时钟、OS 定时器、内部锁或线程安全容器。

所有回调同步执行，不允许重入、关闭或销毁所属实例。跨任务访问和 ISR/任务缓冲交接由应用串行化。不同实例共享的驱动或 provider 也由应用负责同步。

## PHY 所有权

PHY TX 接收完整帧，在返回前必须消费或复制全部字节，不允许保留指针供 DMA 异步读取。当前 SDK 不提供异步 TX completion、generation 或 submission-ID 所有权模型。异步硬件通过驱动自有队列适配为此同步接纳契约。

每个独立 PHY 描述符对应一个 link/parser/RX 状态；共享同一描述符的路由共用该 link。RX 非阻塞或执行有界，输出长度不得超过调用者容量。

## Workspace 和借用对象

动态、静态实例共用精确分区计划。`xgl_create()` 仅向显式 backend 申请一次完整 workspace，随后由 `xgl_init()` 初始化；`xgl_init_static()` 使用调用者对齐存储并完成初始化。初始化和运行时不向外部 backend 继续申请，也不隐式扩容。销毁动态实例一次性归还 workspace，静态存储仍归调用者。

实例借用不可变配置，配置、路由/PHY/provider 描述符及上下文必须活到销毁结束，且不能与 workspace 重叠。可靠 payload、待推进消息、乱序包及重组消息由各自独立的固定池拥有，资源类别不能互占预留容量。

公开容量同时限制单 peer 窗口、全局可靠 TX、全局乱序 RX、消息长度、重组槽和共享消息字节接纳量。固定最大尺寸槽位保证任意释放顺序下复用，不承担 arena 碎片风险。字节接纳预算小于物理预留时，也不据此缩减必要槽位。

## 接纳和可靠性

可靠包只有在应用接纳或进入协议自有有界存储后才 ACK。已接纳的数据遇到应用 BUSY 必须继续保留并重试，不能静默丢弃。分片发送按窗口持续推进，整条可靠消息可以超过当前包窗口。

scope 由远端节点、connection ID 和 epoch 标识。使用过可靠包编号的 scope 不因空闲计时静默回收；失败后保留失败身份，不能重置序列号后继续使用。调用者显式关闭未认证 scope、排空旧流量并使用新 epoch。认证模式关闭可信会话，并遵守 key/nonce 域不复用和重启新鲜性要求。

## 资源验收

目标设备总预算为 64 KiB Flash / 8 KiB RAM。更小 Boot 的 8 KiB Flash / 1 KiB workspace 是独立优化目标，未测得满足之前不得当成保证。

`tools/boot_footprint` 提供真实 Cortex-M0 链接、目标 ABI 布局、map、单函数栈和无堆符号证据。它不提供 BSP，也不证明板上执行。完整产品还须计算驱动、认证实现、Flash 更新缓冲、全部调用链和中断栈。
