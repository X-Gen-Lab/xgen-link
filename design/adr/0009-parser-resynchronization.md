# ADR 0009：从保留字节重新同步帧头

状态：已采纳。日期：2026-10-01。延续 [ADR 0008](0008-datalink-runtime.md)。

## 问题

候选帧的 CRC 失败不能证明缓存中的所有字节都无效。丢失一个 CRC 字节会把下一帧的 `A5` 当作 CRC；丢失两个会吞入 `A5 5A`。错误的长候选还可能包含多帧有效数据。以前的整缓存 reset 会丢弃这些恢复机会。

## 决策

1. 正常接收继续遵守当前候选的长度，不在合法载荷内抢占 magic。固定头、扩展、容量和完整 wire 校验仍由同一检查路径处理。
2. 当前候选失败时保留原始诊断和缓存，统一进入私有 RECOVER 状态。由 advance 从候选起点之后寻找 magic 对，末尾单个 `A5` 也可保留；没有可能起点时回到搜索状态。拒绝和恢复不重复扫描缓存。
3. `xgl_parser_advance_view` 扫描缓存，优先选择最早的完整有效帧。若不存在完整帧，保留最早的可能半帧，再回到正常增量接收。更早但未完成的伪长候选不能挡住已经完整且通过校验的后帧。
4. 扫描只选择候选，不逐字节搬运。确定候选后至多压缩一次缓存；完整 view 的指针同步重定位，无需再计算该帧 CRC。每次交付只释放该帧，保留后续帧及尾部半帧。
5. feed 返回 ERROR 后先记录诊断；返回 COMPLETE 后先同步交付。随后 advance，直到 INCOMPLETE 才继续 feed。COMPLETE/RECOVER 时误调用 feed 返回 ERROR，不消费新字节。显式 reset 仍表示丢弃全部缓存。旧私有调用方必须遵守此契约。
6. `get_frame` 返回当前完整帧的精确长度，不能把缓存余量作为帧长。缓存长度包含后续字节，两者含义不同。
7. 恢复扫描不为每个假 magic 重复报告错误。完整 wire 帧经过上层 BUSY、认证或准入拒绝后仍按完整帧消费，不扫描其载荷。直接输入完整原始帧的入口仍只验证这一帧。
8. 缓存后缀保守继承原候选 timestamp；恢复不续期。不增加逐字节时间记录，因此不能还原后缀的真实到达时间，可能比它实际开始接收的时间更早过期。正常 `A5 A5 5A` 重叠仍使用第二个 `A5` 的实际接收时间。

## 资源与执行边界

沿用调用方缓存与原 parser 字段；无递归回放、第二份 MTU 缓存、动态内存或后台任务。借用 view 在消费后 advance 时失效，回调不得重入同一实例或修改缓存。

magic 搜索是线性的，但多个候选的 CRC、扩展校验及多帧移位可导致最坏二次工作量。每次恢复受缓存容量约束，循环始终推进起点或消费完整帧；本设计不声明严格 MCU 周期上界。RX budget 限制新读取字节，不能等同于恢复 CPU 预算。真实产品需按容量、输入速率、调度和看门狗验证。

wire CRC 通过只证明格式和校验通过，不证明发送者可信，也不能消除随机 CRC 碰撞或歧义。认证策略继续由 security/network 执行。超时仍按既有策略丢弃过期候选；本决策没有增加“超时后恢复缓存”的行为。

## 验证

GoogleTest 链接真实生产实现，覆盖缺失 CRC 字节、坏头内含新头、缓存多帧排空、尾部保留、完整帧优先、容量边界、假 magic、重叠及回绕期限、正常载荷内嵌帧、BUSY/认证拒绝和私有 API 误用。

验收分别记录四 profile、编译器、sanitizer、覆盖率、静态分析与最终 ARM ELF；不以主机耗时替代 MCU 最坏周期，不通过删除历史用例或放宽资源预算换取通过。结果见[重新同步验证](../validation/parser-resynchronization.md)。
