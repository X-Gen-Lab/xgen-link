# ADR 0013：可选执行预算、scope 观测和消息存储

- 状态：已实施，验证证据见根目录实施状态
- 日期：2026-10-02
- 前置：[ADR 0012](0012-transport-resource-contract.md)

## 问题

按读取字节数限制工作，不能限制坏帧恢复时的候选验证次数；维护一次遍历可能提交多个重传包。固定重组期限与业务时延不匹配，而只限制单包重试次数不能限制持续背压的消息忙期。应用还需要区分连接、会话与资源占用，而旧接收回调只携带节点和类型。

分片 workspace 默认按 peer 和重组容量保留完整消息槽。降低消息字节预算不能降低这些槽的预留量。认证可选实例也不能仅凭收到认证数据，就自动推导反向发送必须认证。

## 决策

1. 使用 `XGL_ENABLE_ADVANCED_RUNTIME` 显式选择本组能力，所有 profile 默认 OFF。生成配置头、target、安装包与构建身份共同约束该选项；不允许消费者通过宏自行改变安装库。保留 `xgl_config_t` 的现有 ABI。
2. 独立 `xgl_instance_options_t` 包含版本、描述符尺寸、配置 ABI 和构建身份。配置及 options 由实例借用，销毁前不可修改。新创建入口先检查描述符，再验证并测量完整存储，最后分配；静态初始化与拥有 workspace 的路径共用计划。
3. `xgl_step_bounded()` 增加每链路 parser 候选预算及实例 transport 维护提交预算。保存恢复游标和原读取时间，未处理数据留在已有 parser cache，不再分配第二份 MTU 缓冲。维护按 peer 轮换起点；期限清理不受零提交预算阻止。单次 CRC、回调、RX 触发 ACK、应用直接发送和列表扫描仍不属于 CPU 周期上限。
4. `reassembly_timeout_ms` 从第一片起计，零保留 5,000 ms 默认值。`tx_lifetime_ms` 为 scope 的可靠发送忙期绝对期限，零关闭；第一份接纳的可靠工作开启，新增工作不延期，全部可靠包及消息尾部排空后结束。它不是每条消息独立的交付期限。
5. scoped 接收回调优先于已有两种回调，携带源节点、connection、epoch、类型和可靠属性。BUSY 后重试保留身份。scope 失败及可靠 TX 排空通过单独事件报告；ACK 排空不代表远端业务完成。回调均同步、不可重入、不可销毁实例。
6. `tx_message_slots`、`rx_message_slots` 独立减少最大尺寸消息槽，零保留旧值；不得超过旧容量上界。RX 槽由活动重组和已完成待接纳消息共享。容量不足按已有背压/资源错误返回，关闭 scope 释放其资源。peer、在途包及逻辑字节预算仍独立生效。
7. `xgl_resources_get()` 无分配地遍历当前实例；报告占用对象数和有效 payload 字节，不将其冒充预留 RAM 或累计峰值。预留量仍由 `xgl_memory_report*()` 给出。
8. `protect_installed_scopes` 只使用显式安装的安全 scope：同一 exact scope 的 TX、RX 和布局一致要求认证；关闭后保留占用记录并禁止明文降级。未安装 scope 在全局可选模式下仍可用明文；全局 `auth_required` 语义保持。收到 HELLO 或数据不建立信任。
9. reliable 全量清理一次清空索引桶后释放拥有记录，避免逐条删索引在碰撞情况下形成二次遍历；单包删除和目标隔离保持。

## 边界和验收

关闭扩展时不增加 parser/peer/instance 常驻字段，默认 Boot ELF 继续使用原预算。开启时单独量测，不能用默认探针代替扩展调用图；裸 MCU、DMA、RTOS 唤醒、真实密码 provider 和完整产品 Boot 由产品验收。

新增行为有独立 RED/GREEN、历史回归、四 profile ON/OFF、安装 C11 消费与编译身份检查。性质测试保留种子。CI 配置与本地执行结果、远端运行结果分别报告。

安全槽关闭记录不能直接回收，否则可能复用 nonce 域；密钥更新、重启新鲜性和应用事务确认仍由明确的产品契约承担。本决策不引入运行时插件系统、线程、自动堆或动态依赖下载。
