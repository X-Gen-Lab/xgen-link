# ADR 0011：传输准入、延迟恢复与有界存储

- 状态：已实施
- 日期：2026-10-01
- 范围：transport、协议内存服务、工作区规划与资源探针

## 背景

原有 ACK 接收能够同步发起重传或继续发送分片，叠加接收和发送调用栈。部分发送拒绝留下空 peer；接收侧对保留类型、可靠广播、重复 FRAGMENT 和包号耗尽的处理也不完整。维护错误仅通知回调，调用者不能从 `xgl_step()` 返回值判断终止性失败。

窗口确认位另行分配，乱序载荷和扩展分开保存；分片对象还重复保存同一个消息长度。这些存储的生命周期已经由 peer 或报文所有者确定，无需独立管理。

## 决策

1. 接收在准入前检查协议语义。保留类型、可靠广播、重复或无效 FRAGMENT 元数据提前拒绝；可靠 DATA 的 `UINT32_MAX` 包号保留，不允许回绕重新使用历史身份。完整扫描扩展后才能创建 peer、更新顺序或缓存数据。
2. 发送失败仅回收本次调用新建且仍可回收的空 peer。已存在、有历史、有待确认数据或失败的 scope 保持既有生命周期，必须显式关闭后才能重新使用。可靠广播在发送前返回 `INVALID_PARAM`。
3. ACK/SACK 接收先验证完整反馈，再释放确认记录、推进窗口并标记快速重传。实际重传与后续分片发送统一由维护阶段执行；公开 `xgl_step()` 可在同一次调用中于接收栈退出后完成维护。可立即执行的工作发布零延迟 deadline。
4. 重复 SACK 不覆盖 PHY BUSY/NO_MEMORY 造成的延迟，也不再次消耗重试次数。ACK 或 close 释放记录时自然取消尚未执行的重传。成功提交后才计入重试次数并更新退避。
5. 维护继续服务其他 peer，并优先返回本次第一个硬错误；没有硬错误时，返回第一个即时反馈失败。已拥有数据的暂时背压保持存储、等待重试，不伪装成终止性失败。缓存交付显式区分应用暂时拒绝与交付后的 ACK 提交失败，不能仅按 BUSY/NO_MEMORY 错误码忽略结果。ACK 发送失败不能撤销已经接受的数据或导致重复交付。
6. 确认 bitset 内嵌窗口，保持私有 128 槽能力，不引入可变长对象。公开报告的 `window_bytes` 保留且恒为零，相关存储计入 `peer_bytes`。删除窗口分配器及工作区池。
7. 乱序节点拥有一个载荷加 TLV 的连续存储块；使用前检查指针、加法溢出和帧预算。两个借用 view 只指向这个拥有的块，释放一次。删除独立 RX 扩展分配器及池。
8. 分片对象统一使用 `message_len`，不降低区间表容量或改变预算收费生命周期。完成但尚未被上层接受的消息继续占用重组预算，终止性失败释放一次。
9. TX plan 只保存后续发送需要的结果。ACK/SACK 局部缓冲按实际 wire 上界声明；继续调用共同编码器，不复制协议编码逻辑。快速重传实现只在 runtime 文件内可见。

## 结构与兼容性

保留生命周期、peer、TX、RX、ACK、runtime、可靠队列、窗口、RTT 和分片算法的既有文件边界。此次不新增调度服务、后台线程或通用消息总线，也不把公共组件代码复制回协议。

wire v3、公开函数和配置布局保持不变；原来接受的无效输入现在拒绝，维护错误返回和 ACK 后续发送时机有意收紧。私有窗口初始化、内存服务和结构布局发生变化，内部消费者需随本次一起重编译；公开报告分类的变化已注明。

Full/Lite 的队列索引、重组区间容量、RTT/RTO 算法和可靠窗口能力不削减。Boot 继续通过构建裁剪认证、转发、分片、乱序和统计；本次不新增另一套 Boot 协议。

## 验证与限制

GoogleTest 覆盖无副作用拒绝、失败回收、接受后 ACK 失败、所有权背压、重复反馈、ACK/close 取消恢复、终止错误、多个 peer、公用 step、静态工作区及区间合并。保留全部历史测试名，历史同步发送断言迁移到明确维护阶段。

最终 ELF、主机矩阵、TDD 检查点与调用栈分析见[传输优化验证](../validation/transport-optimization.md)。单函数 `.su` 和 1 KiB 预留栈不能证明板级峰值；应用回调、驱动、调用者和 ISR 仍由产品预算验收。
