# ADR 0012：传输事实、发送预准入与编译资源契约

- 状态：已实施；默认 Boot LTO 的既有 Flash 预算仍未通过
- 日期：2026-10-02
- 范围：transport、配置身份、安装消费与资源探针
- 前置：[ADR 0011](0011-transport-admission-recovery.md)

## 背景

同一个 peer 可以同时拥有可靠发送历史和非可靠分片。不能仅凭 peer 有可靠历史，就把任何重组超时判为整个可靠 scope 失败。分片属于同一消息时，其可靠属性也必须保持一致；反馈失败不能撤销已接受的事实。

原发送流程在检查全部本地资源之前发送 HELLO。后续容量拒绝可能占用对端空 peer；仅依赖产品配置的普通 idle timeout，不能保证这种预约最终释放。

固定 128 槽确认位、默认索引桶数和 RTT 状态适合通用构建，但受限镜像需要显式裁剪。只改宏或运行时配置会使消费者无法判断安装库的真实布局和能力。

## 决策

1. 重组对象记录已接纳消息的可靠属性。同一 scope/message 的类型、总长度与可靠属性不可改变；活动重组与已拥有的乱序分片在 ACK/SACK 之前校验。ACK 提交失败仍保留接受事实。
2. 非可靠重组超时释放该消息并报告超时，不终止同 peer 的可靠历史或待确认发送。可靠重组超时保持终止性 scope 失败。fragment 维护先把过期对象从活动列表摘出，再调用 transport 清理所属 scope，最后释放对象，避免清理过程中失效的遍历指针。
3. 可靠发送在 HELLO 前完成本地预准入。普通发送预留记录和载荷；分片发送预留完整消息副本以及首片记录、载荷与扩展。本决策不预分配未来每一片的记录。失败释放本次拥有的资源，不改变既有 scope 的历史和错误优先级。
4. 收到 HELLO 的空 peer 使用独立 5,000 ms 预约期限；起点为第一次 HELLO，重复 HELLO 和被应用拒绝的 DATA 不续期。普通 idle timeout 为零时仍回收预约；有已接纳历史、拥有数据或终止状态的 peer 不按空预约回收。回收和 deadline 查询使用同一到期规则。
5. 增加受控编译选项：`XGL_RELIABLE_INDEX_BUCKETS` 为 AUTO 或 1/2/4/8/16/32；`XGL_TRANSPORT_WINDOW_CAPACITY` 为 AUTO 或 1/8/16/32/64/128；`XGL_ENABLE_ADAPTIVE_RTO` 为 ON/OFF。AUTO 窗口保持所有 profile 的 128 槽，索引 AUTO 保持 Boot 1、Lite 8、Embedded/Full 32 桶，RTO 默认 ON。
6. 关闭自适应 RTO 时不保存 peer RTT 状态，不按 ACK 更新估算；请求显式 timeout 或配置默认值决定初始超时，重试退避保持。运行时窗口不得超过编译容量，确认位按容量向上取整，不引入可变长对象或额外堆服务。
7. 导出解析后的资源身份、target 属性和安装头检查。默认构建身份 301–304 保持；非默认组合通过 profile、桶数、窗口、自适应 RTO、RX chunk 和 fallback 生成独立身份。target、安装头与运行时入口分别拒绝不一致的消费者。产品继续选择唯一依赖版本，不由协议下载或重复引入公共组件。
8. RX 的私有声明归属 `xgl_transport_rx_internal.h`。顺序分片复用已解码元数据；乱序查找复用插入位置，不新增缓存字段。ACK_RANGE 先验证全部声明，再利用发送记录顺序合并遍历；SACK 遍历实际待确认记录。已知存活记录的 ACK 和 TX 回滚按拥有对象删除，独立 reliable 的目标/包号删除接口保留。
9. footprint 格式升级为 6，记录实际资源身份、容量、桶数和 RTO 开关。预算可要求精确匹配上述字段。新增 small 预算只接受窗口 1、桶 1、固定 RTO 的显式组合，原默认预算不放宽、不替换；CI 同时执行两个组合的 MTU/LTO 矩阵，超限继续返回失败。

## 结构与兼容性

wire v3、公开配置结构和发送 API 保持。消息属性混用现在提前拒绝，HELLO 空预约生命周期有意收紧。新选择改变私有布局和可支持窗口，所有消费者必须使用对应生成头并重编译。

独立 fragment 的原接口继续可用，transport 通过 scoped 入口提供可靠事实。独立 reliable 保留多目标语义，不能因为生产 transport 使用单 scope 队列，就悄悄删除共享内部消费者的目标隔离行为。

没有加入运行时服务发现、线程、通用消息总线或另一套 Boot 协议。容量缓存、轮转调度和维护配额需要产品的 WCET、吞吐与公平性证据；本次不为这些候选增加常驻状态。发送返回本地接受不等于远端业务执行完成，完成观测需要单独的应用契约。

## 验证与限制

真实 RED/GREEN、双端集成、各 profile、固定 RTO 安装消费、编译身份拒绝、最终 ELF 和调用栈证据见[实施验证](../validation/transport-resource-refinement.md)。默认和 small 的功能选择分别报告，不能直接把不同选择的 Flash 差值称为同功能优化。

默认 LTO Flash 超出既有 12,800 B 门槛；small LTO 仅有 12 B 余量。8 KiB Flash 的更小 Boot 目标仍未达到。1 KiB 预留栈不是完整调用链峰值，真实板卡、驱动回调、ISR、DMA、密码 provider 和断电恢复仍由产品验收。
